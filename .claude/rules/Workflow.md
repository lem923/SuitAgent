# 工作流系统配置

**版本**: 2.0
**最后更新**: 2026-04-02
**说明**: 定义用户需求识别、Agent自动路由和复合工作流执行机制

## 路由机制概述

主Agent在接收到用户需求时，应首先进行需求分析，判断是单一功能需求还是复合工作流需求：

- **单一功能需求**: 直接路由到对应专门Agent
- **复合工作流需求**: 制定工作流组合，按顺序调用多个Agent

## 立即路由规则表

### 📝 Writer Agent - 文书起草编排器（orchestrator 模式）
**触发关键词**:
- 诉讼文书：写/起草 起诉状、答辩状、上诉状、再审申请、检察监督申请、代理词、质证意见、财产保全申请、证据清单、仲裁申请书、反诉状
- 律所对客户文书：写/起草 律师函、催款函、委托合同、委托代理协议、授权委托书、谈话笔录、法律意见书、调解协议、离婚协议、刑事格式文书
- 通用：写/起草 法律文书

**路由规则**: 检测到上述任一关键词 → 立即调用 Writer Agent

**消歧（与其他 agent 的边界）**:
- "再审申请" / "检察监督" / "上诉" 在 Writer 触发**仅当用户意图是"起草文书"**（含动词"写"/"起草"/"拟"）；意图是"评估能不能再审/上诉/监督的可行性" → 走 JudgmentAnalyzer
- "质证意见" 在 Writer 触发**仅当用户说"写/起草质证意见书"**；意图是"对证据出质证意见" → 走 EvidenceAnalyzer

**Writer 内部分流（orchestrator）**:
- 诉讼文书 → Writer 调起 `cn-litigation-drafting` skill（必需依赖）
- 律所对客户文书 → Writer 调起 `cn-firm-documents` skill（必需依赖）
- 详见 `.claude/agents/Writer.md` 的"文书路由表"

### 🔬 JudgmentAnalyzer Agent - 裁判文书深度审查器
**触发关键词**:

**消歧（与 Writer 的边界）**:

**JudgmentAnalyzer 内部流程（orchestrator 模式）**:
- 调起 `cn-judgment-analysis` skill 完成 5 步评审（文书画像 → 争议反向还原 → 证据认定拆解 → IRAC 重建 → 救济路径评估）

- **本 agent 不是质量审查器（Reviewer）**，是判决书的法律层评审

**识别关键词**：原告、被告、诉讼请求
**自动场景**：被告应诉
**优先级**：高

### 2. 证据材料识别
**识别关键词**：证据、附件、证明
**自动场景**：证据质证
**优先级**：高

### 3. 庭审笔录识别
**识别关键词**：庭审、审判员、当事人
**自动场景**：庭审后分析
**优先级**：中

### 4. 判决书识别
**识别关键词**：判决、裁定、法院认为
**自动场景**：判决分析
**优先级**：中

### 5. 诉前沟通记录识别
**识别关键词**：委托、咨询、初步沟通、意向
**自动场景**：法律服务方案
**优先级**：中

### 6. 诉讼中沟通识别
**识别关键词**：客户反馈、对方反应、新情况、补充信息
**自动场景**：策略优化
**优先级**：中

### 7. 原告案件材料识别
**识别关键词**：委托起诉、准备起诉、拟起诉、材料清单
**自动场景**：原告起诉
**优先级**：高

### 8. 委托确定识别
**识别关键词**：确定委托、签署委托、办理委托、委托材料
**自动场景**：制作委托材料
**优先级**：高

## 一键启动方式

### 方式一：上传文件自动识别
**示例**：用户提供文件（例：起诉状.pdf）
**流程**：自动识别 → 自动选择工作流 → 自动执行 → 生成报告

### 方式二：明确指定场景
**示例**："我收到了对方的起诉状，需要应诉"
**流程**：识别为"被告应诉" → 启动对应工作流 → 自动执行

### 方式三：描述需求自动分析
**示例**："我想分析这个案件的争议点，并准备答辩"
**流程**：解析需求 → 自动规划流程 → 执行

## 识别精度要求

- **最低关键词匹配数**：2个
- **模糊匹配**：启用
- **上下文分析**：启用
- **置信度阈值**：0.7

## 场景优先级定义

### 高优先级场景
1. 被告应诉
2. 证据质证
3. 原告起诉
4. 制作委托材料

### 中优先级场景
1. 庭审后分析
2. 法律服务方案
3. 策略优化
4. 判决分析

## 特殊情况处理

### 多场景冲突
**处理方式**：按优先级排序，提示用户确认
**优先级顺序**：被告应诉 → 证据质证 → 原告起诉 → 制作委托材料

### 场景不明确
**处理方式**：请求用户澄清或提供更多信息
**回退机制**：使用通用案件分析流程

### 混合文档
**处理方式**：分别处理各部分内容
**处理原则**：主文档确定主要场景，辅助文档作为补充

## 复合工作流场景定义

### 场景1：被告应诉

**描述**：收到起诉状时的完整应诉流程

**触发关键词**：收到起诉状、需要应诉、准备答辩

**工作流步骤**：
1. **DocAnalyzer** (分析起诉状) → [内嵌验证]
2. **IssueIdentifier** (识别争议焦点) → [内嵌验证]
3. **JiubufaAnalyst** (九步法深度结构化分析，仅在复杂阈值命中时触发) → [可选]
4. **Researcher** (法律检索) → [内嵌验证]
5. **Strategist** (制定应诉策略) → [专项审查]
6. **Writer** (起草答辩状) → [专项审查]
7. **Reviewer** (自动触发，质量审查) → [跨Agent质量把关]
8. **Summarizer** (生成摘要) → [内嵌验证]
9. **Reporter** (整合报告) → [最终审查]

**预期输出**：争议焦点分析、法律检索报告、应诉策略方案、答辩状草稿、证据清单、完整案件报告

### 场景2：新证据质证

**描述**：收到新证据时的质证分析流程

**触发关键词**：有新证据、需要质证、证据审查

**工作流步骤**：
1. **DocAnalyzer** (分析新证据)
2. **EvidenceAnalyzer** (证据分析)
3. **Researcher** (针对性法条研究)
4. **Writer** (质证意见书)
5. **Summarizer** (证据摘要)

### 场景3：庭审后分析

**描述**：庭审结束后的分析与策略调整

**触发关键词**：庭审结束、分析庭审、调整策略

**工作流步骤**：
1. **DocAnalyzer** (庭审笔录分析；如已下达判决书一并抽事实)
2. **JudgmentAnalyzer** (判决书深度评审，仅在 post-judgment 阶段触发) → [可选]
3. **EvidenceAnalyzer** (对比前后证据)
4. **Strategist** (调整策略；如有 JudgmentAnalyzer 救济路径表则基于其选具体救济)

### 场景4：法律服务方案

2. **IssueIdentifier** (识别客户需求)

**描述**：诉讼过程中的策略调整和优化

### 场景6：原告起诉

**描述**：完整起诉流程，从材料分析到起诉包生成

## 路由执行流程

### 路由优先级规则

1. **关键词匹配优先**: 精确匹配触发词 → 立即路由
2. **场景识别优先**: 匹配复合场景 → 启动预设工作流
3. **智能分析最后**: 无法自动识别 → 询问用户并智能分析

### Agent调用标准

**单一任务调用**：检测到单一功能触发词 → 立即路由到对应Agent → Agent完成任务 → 返回结果

**复合任务调用**：检测到复合场景触发词 → 启动预设工作流 → 按顺序调用多Agent → Reporter整合结果 → 返回综合报告

## 工作流执行原则

1. **主Agent编排**：工作流由主Agent统一编排，Subagent只返回结果，不调用其他Subagent
2. **上下文继承**：主Agent将前序Subagent的结果传递给后续Subagent，保持分析一致性
3. **增量更新**：复用历史分析结果，提高效率
4. **质量保证**：每个Agent都具备内嵌验证或专项审查机制
