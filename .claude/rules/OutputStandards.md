# Agent输出标准规范

**版本**: 1.8
**最后更新**: 2026-05-11
**说明**: 定义所有Agent输出文件的命名规范、格式标准和质量要求（注：Agent目录映射关系详见 AgentMapping.md）

## 🎯 文档职责说明

本规范专注于**输出文件本身的标准**：
- ✅ 文件命名规范（日期前缀、格式）
- ✅ 文件内容格式（Markdown结构、模板）
- ✅ 质量要求和检查清单

**Agent目录映射关系**详见 [`AgentMapping.md`](./AgentMapping.md)

## 🚨 核心输出原则

### 文件格式要求
- **必须输出.md（Markdown）格式文件**
- **不要输出.json格式文件**
- 所有Agent输出均应使用Markdown格式进行结构化展示

### 文件命名规范

#### 🚨 日期前缀强制要求
**所有Agent输出文件名必须以日期前缀开头，格式为：YYMMDD（空格）文件名**

- **日期格式**: YYMMDD（年月日各两位）
- **分隔符**: 日期后必须加一个空格
- **示例**: 2026年1月1日 → `260101 `
- **获取方式**: 使用 `date "+%y%m%d"` 获取当前日期

#### 通用命名规则
- **日期前缀**: 必须以 `YYMMDD ` 开头
- **使用中文描述**: 文件名应使用简洁明了的中文描述
- **避免特殊字符**: 文件名中避免使用 `/ \ : * ? " < > |` 等特殊字符
- **统一后缀**: 所有文件统一使用 `.md` 后缀

#### 📂 文件类型分类

**一次性输出文件**（需日期前缀）:
- 分析报告、法律文书、摘要等一次性生成的文档
- 每次生成为新版本，保留历史版本

**持续维护文件**（无需日期前缀）:
- 工时记录、期限管理等长期更新的文件
- 单一文件持续更新，不保留历史版本

## 案件文件夹命名规范

> v1.10.1+ 新增。new-case skill 与 /organize-case 命令均严格遵循本规范。

### 严格格式

```
{YYMMNN} {原告简称} 与 {被告简称} {案由}
```

### 字段规则

| 字段 | 规则 |
|------|------|
| **YYMMNN** | 年月顺序号，**6 位数字**（年 2 位 + 月 2 位 + 当月案件自然顺序号 2 位）|
| 空格 | 字段间用**单个空格**分隔（不接受多空格 / Tab / 半角空格之外的字符）|
| **原告简称** | 不超过 6 字；多原告取最重要 1 个或用"等"（如`王某 等`）；公司用全称简化 |
| **与** | 单字分隔符，**前后各一空格** |
| **被告简称** | 同原告简称规则 |
| **案由** | 标准案由名（参《民事案件案由规定》），不超过 10 字 |

### NN（自然顺序号）规则

- NN = **本所当月内案件按收案时间顺序递增**（不按字母 / 案由 sort，不按客户首字母）
- 从 **01 起算**，每月独立重置
- **不跳号**：同月已有 260501-260507，下一个新案件就是 260508
- 一旦使用不回收：即使案件撤销 / 弃案，该编号不复用
- 重整理模式下检测当月已用 NN，建议下一个未用编号（取最大 + 1）

### 特殊场景命名变体

| 场景 | 命名变体 |
|------|---------|
| **行政诉讼** | `{YYMMNN} {原告} 诉 {行政机关} {案由}` —— 用"诉"替代"与" |
| **婚姻家事** | 通常双方都是当事人，保留双名：`{YYMMNN} {夫} 与 {妻} 协议离婚` |
| **多原告** | 取最重要的或用"等"：`{YYMMNN} 王某 等 与 {被告} {案由}` |
| **多被告** | 同上：`{YYMMNN} {原告} 与 李某 等 {案由}` |
| **仲裁** | `{YYMMNN} {申请人} 与 {被申请人} 仲裁`（不用"诉"或"与"以外的字）|
| **涉外 / 跨境** | 当事人按当地实务习惯简化（如 HK 上市公司可用 ticker + 简称）|

### 标准例

```
260221 张家宁 与 pokebone 模型 著作权
260315 甲公司 与 乙公司 合同纠纷
260509 王实 与 王琨 协议离婚
260512 北京 XX 局 诉 王某 行政处罚
```

### 反例与修正

| 反例 | 问题 | 修正 |
|------|------|------|
| `260507 华雄公司 土地使用权转让纠纷` | 缺 "与 被告" | `260507 华雄公司 与 [对方] 土地使用权转让纠纷` |
| `260508 赵利平劳动纠纷` | 字段间无空格 + 缺 "与 用人单位" | `260508 赵利平 与 [用人单位] 劳动合同纠纷` |
| `王荣 劳动纠纷` | 缺 YYMMNN + 缺 "与 用人单位" | `[YYMMNN] 王荣 与 [用人单位] 劳动合同纠纷` |
| `260221 王某诉李某合同纠纷` | 不应用"诉"（民事用"与"，行政诉讼才用"诉"）| `260221 王某 与 李某 合同纠纷` |
| `260221 王某 vs 李某 合同纠纷` | "vs" 不在规范内 | `260221 王某 与 李某 合同纠纷` |
| `26022 王某 与 李某 合同纠纷` | YYMMNN 必须 6 位 | `260221 王某 与 李某 合同纠纷` |

### 验证脚本

```bash
# 一键合规检查：
ls -d /Volumes/EXTERNAL/cowork/SuitAgent/*/ | grep -vE "^.*/(\.git|\.claude|cn-firm-documents|tmp|vscode-extension)/?$" | while read dir; do
    name=$(basename "$dir")
    if [[ ! "$name" =~ ^[0-9]{6}\ .+\ (与|诉)\ .+\ .+$ ]]; then
        echo "❌ 不合规：$name"
    else
        echo "✅ 合规：$name"
    fi
done
```

### 与 .gitignore 的关系

- 标准合规命名（含 YYMMNN 数字前缀）由 `.gitignore` 第 46 行 `[0-9][0-9][0-9][0-9]*/` 捕获
- 非标准命名（如"王荣 劳动纠纷"）由兜底规则 `*纠纷/` / `* 与 */` 等捕获
- 重整理后改为标准命名时，gitignore 自动覆盖，无需额外动作

## 📝 输出格式标准

### Markdown结构规范

#### 1. 标题层级
- **一级标题**: `# ` 用于文档主标题
- **二级标题**: `## ` 用于主要章节
- **三级标题**: `### ` 用于子章节
- **四级标题**: `#### ` 用于详细条目

#### 2. 内容结构
每个Agent输出应包含以下标准结构：

```markdown
# [文档主标题]

## 核心要点/关键信息
[总结性内容]

## 详细内容
[具体分析内容]

## [Agent特定的章节]
[根据Agent类型定制的专业内容]

## 总结/建议
[结论性内容]
```

#### 3. 格式规范
- **列表**: 使用 `-` 或 `*` 创建无序列表
- **强调**: 使用 `**粗体**` 突出重点
- **引用**: 使用 `> 引用内容` 标注重要引用
- **代码**: 使用 `` `代码` `` 标注技术术语或函数名
- **分隔线**: 使用 `---` 分隔重要章节

## 🔄 质量要求

### 内容质量标准
1. **准确性**: 确保所有信息准确无误
2. **完整性**: 涵盖所有必要的分析要素
3. **逻辑性**: 内容结构清晰，逻辑严密
4. **专业性**: 使用准确的法律术语

### 格式质量标准
1. **一致性**: 所有Agent遵循相同的格式规范
2. **可读性**: 结构清晰，易于阅读和理解
3. **标准化**: 统一使用Markdown格式
4. **完整性**: 包含所有必要的章节和内容
