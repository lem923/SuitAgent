# 签署前核查清单（开发/政企技术采购）

>
> 1. 内容是否与同类目下 contract-copilot 继承文件存在重叠（如有，去重或合并）
> 2. 风险等级标记（如已用 REDLINE/ORANGE/YELLOW 则保留；如用其他符号需统一）
> 3. 是否仍是当前实操偏好（如否，更新或迁移到 personal-preferences.md）

## A. 文件与版本
- [ ] 合同正文、封面、签署页主体信息一致
- [ ] 所有附件已附齐并锁定版本（名称/日期/页数/版本号）
- [ ] 招采链文件已并入或明确引用
- [ ] 如为联合体/分包：责任链、授权链、盖章链完整

## B. 金额与付款
- [ ] 合同总价、税率、含税/不含税口径一致
- [ ] 付款节点对应明确触发文件，不以主观满意或无限期第三方审核为条件
- [ ] 发票类型、开票时间、账户信息、逾期付款后果一致
- [ ] 财政资金拨付延迟条款如存在，配套暂停、顺延、长期延迟后的结算/解除机制

## C. 期限体系
- [ ] 生效、履约、试运行、质保、终止的起算点唯一且不冲突
- [ ] 关键时限均绑定送达/提交/验收申请等客观起算事件
- [ ] "尽快""及时"等宽泛表述已改为可验证期限

## D. 交付与验收
- [ ] 交付物清单完整，且与付款节点衔接
- [ ] 验收主体、流程、时限、材料清单、争议处理机制明确
- [ ] 视为验收条款已绑定"材料齐备 + 已完成应做配合"前提
- [ ] 质保/维护范围、响应时限、重大缺陷定义和重验机制明确

## E. 数据、安全与知识产权
- [ ] 数据来源、处理权限、保密边界、远程接入规则已明确
- [ ] 第三方组件/许可/权属证明齐备
- [ ] 成果归属、使用权、源代码/图纸/文档交付边界与合同类型一致
- [ ] 不能证明权属的技术成果，未写入绝对性承诺

## F. 违约、解除与争议解决
- [ ] 违约金基数、比例、上限、与损失赔偿关系一致
- [ ] 解除条件客观可证，补救期和后果明确
- [ ] 律师费、保全费、鉴定费等维权成本条款已检查
- [ ] 争议解决、送达地址、电子送达规则已落实

## G. 许可条款（如适用）
- [ ] 权利证书和权属链证明已附
- [ ] 质押/共有/独占许可已披露并处理
- [ ] 许可类型和四维范围完全明确
- [ ] 侵权处理路径和赔偿责任已定义
- [ ] 终止后使用和存量处理已定义
