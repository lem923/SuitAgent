# 审查人个人偏好与方法模式

> **本文件性质**：项目内置默认审查偏好。同事 fork 本 skill 后，建议把以下内容
> 改成自己的方法偏好与历史经验；条目本身记录的是"审查人个人的合同处理习惯"，与
> `playbook.md` 的"组织/团队标准立场"互补。

## 文件性质

- **作用**：Stage 0 加载时，告诉 Reviewer 当前审查人在合同审查中的方法偏好、历史踩坑、
  常见处理模式
- **粒度**：方法层 + 经验层（不是具体客户事实，不是具体条款条文）
- **保密硬约束**：本文件不得记录具体客户身份、案件编号、合同金额原文

## 默认审查偏好（项目继承自原作者，可由实际审查人覆盖）

> 本节是项目默认审查偏好。所有具体偏好（背靠背付款 / 通知送达 / 数据安全 / 跨境法域选择等）作为开箱即用的默认设置，同事 fork 后可删除本节、改为自己的偏好

### 方法偏好

- 采用 REDLINE（不改不签）/ ORANGE（强烈建议谈判）/ YELLOW（优化项）/ GREEN（提示）分层
- 风险识别应配套 ready-to-insert 替换条款；不接受"建议进一步协商"等空泛措辞
- ORANGE / REDLINE 必须填 fallback 三档（目标 / 可签 / 底线）
- 输出签署前 checklist，覆盖必须修改项、谈判目标、需补全字段、第三方资质核验步骤
- 修订版复审时，确认已解决项、仍未解决项和新增风险
- 用户中途要求改范围时，回溯修正输出（例如从全量审查改为只保留 REDLINE）

### 模板空白项处理

模板合同中的空白字段不当然列为重大风险。区分：

- **预期填写占位符**（如签字日期）：仅列入"待确认事项"
- **影响核心义务的实质性空白**（付款、标的、数量、期限）：列为 ORANGE
- **签署前必须补齐但不构成条款设计缺陷的字段**（联系人、地址）：列入 presign checklist

### 政府、事业单位、国企背景

当客户或交易结构涉及政府、事业单位、国企或财政资金时，重点关注：

- 先票后款、财政拨付、内部审批、预算约束
- 数据安全、保密、敏感数据处理
- 招投标文件、采购文件、合同、附件之间的效力顺位
- 付款延迟与供应商停工/顺延/免责之间的平衡
- 行政审批、资质、备案等专项事项**仅提示风险**，不出确定结论

私营主体或个人委托方不自动套用财政支付逻辑，应按实际交易背景校准。

### 背靠背付款

背靠背付款可能是不可删除的商业要求。**不要直接要求删除**，正确处理方式是结构内缓释风险：

- 设置最长等待期限
- 设置暂停履行或顺延权
- 明确上游未付款不影响已完成工作验收和债权确认
- 隔离非承包方原因导致的付款风险
- 明确通知、证明文件和争议处理路径

### 数据安全

技术服务、软件开发、测试服务、数据集处理合同中，高优先级检查：

- 加密传输
- 访问权限控制
- 项目结束后返还、删除或销毁
- 安全事件通知时限
- 分包方和第三方实验室的数据安全责任
- 敏感数据、气象数据、个人信息或重要数据的监管属性

### 通知与送达

通知和送达条款缺失是高频结构性问题。重点检查：

- 通知地址、联系人、邮箱
- 送达生效时间
- 地址变更通知
- 电子送达与纸质送达优先级
- 与违约通知、验收异议、解除、争议解决的衔接

### 分包、转委托与第三方实验室

涉及主供应商委托第三方实验室、检测机构或分包方时，重点关注：

- CNAS / CMA 等资质持续有效
- 分包或转委托是否经客户同意
- 第三方行为责任是否向主供应商传导
- 报告真实性、独立性、可追溯性
- 资质失效、人员变更、实验室变更时的通知和替代机制

### 跨境合同（PRC ↔ HK / SG / CA）

- PRC 法律 + HK 仲裁的混合管辖结构常见，需判定仲裁条款是否在 PRC 端可执行（《最高人民
  法院关于内地与香港特别行政区相互执行仲裁裁决的安排》）
- HK / SG / CA 法律适用时，按 cross-border-review.md 降级，不引《民法典》具体条文
- 适用法律为加州法时，CCP § 1713 et seq.（PRC 法院判决在加州的承认执行无双边条约，走
  礼让原则）

## 同事 fork 后的本地化指引

1. **删除"默认审查偏好"节中不适合你的部分**，或新建"## 当前审查人：[你的名字]"小节覆盖默认设置
2. 按以下大纲填入你的方法偏好与历史经验：
   - 方法偏好（风险等级、必出措辞要求、必填项）
   - 模板空白项处理
   - 行业 / 客户类型偏好（如金融、互联网、医疗、外贸等）
   - 你常踩的坑 / 历史经验
   - 跨境部分（如适用）
3. 修改 `playbook.md` 中的 14 类 yaml 立场配置
4. 在 `memory.md` 中按合同类型分节累积条目（每条审查后 Stage 4 自动追加）

## 与 memory.md 的边界

- `personal-preferences.md` = 静态的方法偏好（少改）
- `memory.md` = 动态的审查经验积累（每次审查后追加，按类型分节）

两者互补：preferences 写"我偏好怎么做"，memory 写"我做过什么、踩过什么坑"。
