# 初读定位与技能路由

## 合同画像（9 字段）

进入条款级审查前，先提取以下字段。**缺失项不得臆测，标记"待用户确认"。**

| 字段 | 说明 |
|---|---|
| 合同名称 | 标题原文 |
| 合同类型 | 买卖 / 租赁 / 服务 / 知识产权 / 担保 / 借贷 / 互联网 / 婚姻家事 / 房地产 / 建设工程 / 公司投资 / 政企采购 / 其他 |
| 主要领域 | 商事一般 / 政企采购 / 技术开发 / 技术许可 / 公司治理 / 房地产 / 建设工程 / 跨境 / 其他 |
| 适用法律 | 中国法（默认）/ 香港 / 新加坡 / 加州 / 其他 |
| 争议解决 | 法院诉讼地或仲裁机构 + 仲裁规则 |
| 客户身份 | 买方 / 卖方 / 许可方 / 被许可方 / 委托方 / 受托方 / 投资方 / 融资方 / 担保人 / 主债权人 / 其他 |
| 对方主体 | 公司名 + 是否国企 / 政府 / 外资 / 关联方 |
| 合同金额 | 具体数字或估算区间 |
| 期限 | 起止日期或触发条件 |

## 立场确认

如用户未明示立场，第一步提问：

```text
本次审查请问我站在哪一方立场？例如：买方 / 许可方 / 用人单位 / 甲方 / 乙方 / 委托方 /
受托方 / 投资方 / 融资方 / 担保人 / 主债权人。
```

立场一经确定，后续修订建议、风险权重、妥协底线全部据此展开。**不得在同一份报告中切换
立场，也不得用"对双方均有利"稀释客户立场。**

## 审查口径

| 口径 | 适用场景 |
|------|--------|
| 克制 | 主导地位 / 速签场景；只标 REDLINE，ORANGE 提示性，YELLOW 不出 |
| 常规 | 双方对等 / 一般谈判场景；REDLINE+ORANGE+YELLOW 全出 |
| 强势 | 有谈判筹码 / 时间充足；尽列所有可争取项，含 GREEN |

如用户未明示，**默认常规口径**。

## 首轮红旗扫描

深度审查前先整体通读，标记以下**严重问题**（任一命中即升级到 REDLINE）：

- 主体资格瑕疵（无对应资质 / 代理人无权签 / 主体名称前后不一）
- 显失公平条款（单方解除 / 无限连带 / 片面违约金 / 单边管辖）
- 管辖与法律适用冲突 / 仲裁条款无效风险
- 付款、交付、验收节点明显失衡
- 知识产权归属严重偏离行业惯例
- 保证、担保、连带责任主体异常扩大
- 合同性质识别错误（如"综合服务协议"实为股权转让）
- 标的违法或不可处分（被查封 / 国家禁止交易 / 第三方权利负担未披露）

## 多类目命中处理

合同同时含 2+ 类目要素时（常见：政企软件开发 + 嵌套技术许可、
建设工程 + 嵌套担保、股权转让 + 嵌套竞业），**主类目优先 + 次类目叠加**：

- 主类目按表上方优先级判定
- 次类目在审查报告"二、审查立场与范围"的"嵌套专项"列出
- Stage 1 Step 2 中观扫描时叠加加载次类目 checklist
- Stage 1 Step 3 微观条款标记时，问题前缀注明类目（如 `LICENSE-01` / `LABOR-01` /
  `GOV-01`）

## 跨境降级触发

如适用法律为非中国法（HK / SG / CA / 其他），按 `cross-border-review.md` 降级：

- 报告顶部加跨境降级声明
- 法律依据列改为通用法理，不引《民法典》具体条文
- 末尾可加多法域对照表

## 调用 skill 的优先级

如同时有外部 skill 可调（如 `docx` 用于 Stage 3 Execute），按以下优先级：

```text
1. 首选：docx skill（路径 /mnt/skills/public/docx/SKILL.md）— Track Changes
2. 次选：md2word — Markdown 转 DOCX，用于审查意见书的正式版式输出
3. 兜底：直接对话内 Markdown 输出 + 用户自行另存
```
