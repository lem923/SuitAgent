# 签署前必查清单（通用）

> **v1 状态**：本文件 v1 阶段从 3 个 specialized skill（gov-tech-dev / gov-tech-licensing
> / labor-employment）的 presign_checklist.md 提取通用项。各类目专属的签署前必查项留在
> `contract-types/XX-{name}/` 各自的 `*-presign-checklist.md` 中。

## 用法

Stage 1 Step 6 输出 7-section 报告时，第八节"待确认事项"基于本清单逐项核对。如某项命中
（合同未约定 / 留空 / 未提供材料）→ 列入"待确认事项"。

## 通用 7 大类必查项

### 1. 主体资格

- [ ] 双方营业执照 / 身份证 已核实
- [ ] 签字人是法定代表人或具备完整授权（授权委托书已签字盖章）
- [ ] 主体名称在合同各处一致（首部 / 落款 / 印章 / 附件）
- [ ] 关联方 / 代签 / 母子公司情况已识别并妥善处理

### 2. 合同基本要素

- [ ] 合同名称、合同编号、签订日期 已填写
- [ ] 标的描述完整（名称 / 规格 / 数量 / 质量标准）
- [ ] 合同金额清楚（含税与不含税明示，币种明示）
- [ ] 履行期限明确（起止日期或触发条件）

### 3. 付款与交付

- [ ] 付款方式 / 节点 / 比例 已约定
- [ ] 收款账户信息已核对（户名与签约方一致）
- [ ] 发票信息（开票方 / 受票方 / 抬头 / 税号）已确认
- [ ] 交付方式 / 地点 / 验收方式 / 验收期限 已约定

### 4. 违约与解除

- [ ] 违约责任可计算（基数 / 费率 / 天数 / 上限）
- [ ] 解除条件具体（重大违约清单 / 法定情形）
- [ ] 解除后果明确（清算 / 赔偿 / 资料返还）

### 5. 通知与送达

- [ ] 通知地址、联系人、邮箱已填写
- [ ] 通知生效时间已约定
- [ ] 地址变更通知义务已约定
- [ ] 与违约通知、验收异议、解除、争议解决的衔接条款已建立

### 6. 争议解决

- [ ] 适用法律已选定（明示）
- [ ] 争议解决方式（仲裁 / 诉讼）已选定
- [ ] 仲裁机构全称、仲裁规则、仲裁地（如选仲裁）
- [ ] 法院管辖（如选诉讼）符合民事诉讼法第 24-25 条要求

### 7. 附件与生效

- [ ] 附件清单与正文一致
- [ ] 附件优先级与正文冲突解决规则已约定
- [ ] 生效条件明确（签字盖章 / 备案 / 审批 / 登记）
- [ ] 文本份数（双方各持几份）

## 高风险类专项必查项

### 涉财政资金 / 政府采购

- [ ] 招投标文件 - 合同 - 附件三层文件优先级已约定
- [ ] 财政预算批复已取得（合同金额 ≤ 批复金额）
- [ ] 内部审批流程已完成（联签 / 党委会 / 三重一大）

### 涉技术许可 / 知识产权

- [ ] 许可方有完整权利链（专利证 / 软著证 / 转让链）
- [ ] 开源组件清单已披露
- [ ] 第三方权利无瑕疵保证已写入

### 涉劳动关系

- [ ] 劳动合同必备条款（劳动合同法第 17 条）齐备
- [ ] 试用期约定符合法律规定（不超过法定期限）
- [ ] 社保 / 住房公积金 缴纳约定明示

### 涉跨境

- [ ] 适用法律为非中国法时，已按 cross-border-review.md 降级
- [ ] 数据出境合规（PIPL 第 38-39 条 / SCCs / 安全评估）
- [ ] 外汇管制 / 出口管制 / 反垄断专项核查
- [ ] 仲裁条款在 PRC 端可执行性（如约定境外仲裁）

## 验证流程

1. 完成 Stage 1 Step 6 7-section 报告主体后，对照本清单逐项检查
2. 命中"未约定 / 留空 / 未提供"的项 → 列入第八节"待确认事项"
3. 待确认事项数量 ≥ 5 → 提示用户"建议先补齐再签署"，签署结论可能从 ✅ 降为 ⚠️

## 与 contract-types/XX-{name}/*-presign-checklist.md 的关系

各类目下的 `*-presign-checklist.md` 是该类目专属的签署前必查项。本文件是**跨类目通用**
的 7 大类。

调取顺序：
1. Stage 1 Step 6：先按本通用清单核对
2. 按合同类型加载 contract-types/XX 下的专属 *-presign-checklist.md（如有）
3. 两者并集 = 完整签署前必查清单
