# 要件审判九步法案件分析技能

## 0. 强制合规规则（最高优先级，不得违反）

> **任何"案件简单不需要走九步"的判断都是错误的。九步法的价值恰恰在于强制完成机械性结构化分析，避免凭直觉跳跃。简化、合并、跳过任何一步均构成质量缺陷。**

**强制规则**：

1. **必须按 1→9 顺序完整输出**。每一步必须有独立的二级标题（`## 第N步：...`），不得合并、跳跃、调换顺序。
2. **每一步必须填满该步骤规定的输出模板**。即使本案在某步无重大问题，也必须显式输出该步标题和一句说明（如"本步骤无特殊问题：[简述原因]"），不得省略 header。
3. **不得在前几步就给出胜诉率结论**。胜诉概率评估只能出现在第九步。如发现第一至八步有任何"看起来很有戏"或"难度很大"等暗示性预判，必须删除。
4. **完成全部九步后，必须输出末尾自检清单**。清单不通过的，重新补完。
5. **不得用散文叙述替代结构化输出**。所有输出必须按本技能规定的表格、矩阵、清单格式呈现。

启动时直接进入第一步，不要写"好的，我用九步法分析"等开场白。

---

## 1. 核心定位

本技能是**起诉/答辩前的案件结构分析底稿**，模拟法官审理时的思维路径，从请求权基础规范倒推每个构成要件是否能用现有证据填满。输出可直接喂给 `cn-litigation-drafting` 起草文书，或喂给 `cn-judgment-analysis` 比对法院实际归入路径。

**与现有技能的协同**：

```
本技能（案件结构分析）──→ cn-litigation-drafting（生成诉状/答辩/再审）
       ↑                              ↓
       └─── cn-judgment-analysis（判决出来后回头比对）
```

## 2. 方法论简述

要件审判九步法（邹碧华，2010年系统化）是德国请求权基础分析法（王泽鉴体系）的中国司法实操版，本质是民事三段论的操作化分解：

| 阶段 | 步骤 | 三段论对应 |
|---|---|---|
| 找规范 | 1-4 | 大前提 |
| 找事实 | 5-8 | 小前提 |
| 归入裁判 | 9 | 结论 |

详细方法论：见 `references/jiubufa-steps-checklist.md`。
完整应用范例：见 `references/jiubufa-case-study.md`。

## 3. 适用范围

**适用**：合同、物权、侵权、婚姻家庭、继承、公司纠纷、劳动争议等民商事请求权诉讼。

**不适用（应转其他方法）**：
- 行政诉讼（合法性审查逻辑不同）
- 刑事案件（四要件/三阶层）
- 涉外/跨境法律冲突案件（先做准据法分析）

**警示**：政策性强、利益衡量主导的案件（涉政府、群体性、金融稳定），九步法仅作底层结构分析，最终结论必须叠加政策考量并在第九步显式标注政策风险。

## 4. 启动前必做：案情登记

进入九步分析之前，必须先输出"案情登记表"。此表是九步分析的输入，不是九步之一，但缺失则九步无法启动。

**启动读经验库（v1.12.0 闭环读侧）**：案情登记前，先读取本 skill 目录下 `memory.md`。若存在**非"（暂无条目）"的真实条目**，按本案请求权类型 / 案由筛选**最相关 top-3** 纳入九步分析参考；若 `memory.md` 不存在或相关 section 全为"（暂无条目）"，**跳过本步（no-op，不阻断、不污染 context）**。本步**只读不写**；写入由 cn-case-postmortem 结案复盘统一负责。

```markdown
## 〇、案情登记

| 项目 | 内容 |
|---|---|
| 当事人 | 原告：... ; 被告：... ; 第三人：... |
| 用户立场 | 原告 / 被告 / 第三人 / 中立评估 |
| 案件阶段 | 起诉前 / 一审中 / 上诉 / 再审 / 检察监督 / 仲裁 |
| 主要事实摘要 | 200字内 |
| 用户当前诉求 | 引用用户原话 |
| 已提供证据 | 罗列；如未提供，标注"待补充" |
| 关键时间节点 | 时间 → 事件 |

⚠️ 信息缺失说明：以下要素用户未提供，建议补充：[逐条列出]
```

如果案情登记表中的"主要事实"或"用户立场"无法填写（用户陈述过于含糊），**直接停止分析**并向用户提问，不要凭推测填充后强行九步。

## 5. 九步工作流程

### 第一步：固定权利请求

**目标**：将用户陈述的诉求转化为明确、具体、可执行的诉讼请求表述。

**必填输出模板**：

```markdown
## 第一步：固定权利请求

### 1.1 用户原始诉求
> [逐字引用用户陈述]

### 1.2 诉请类型识别
□ 给付之诉（金钱/物/行为）
□ 确认之诉（有效/无效/未生效/撤销）
□ 形成之诉（变动法律关系）
□ 行为之诉（履行/不履行）
（多重诉请则多选）

### 1.3 模糊点排查
| 诉请编号 | 模糊/瑕疵 | 修正建议 |
|---|---|---|
| 1 | ... | ... |

如无模糊点，写"无"。

### 1.4 固定后诉请
一、[精确表述]
二、[精确表述]
三、诉讼费由被告承担

### 1.5 不可执行/不当诉请的剔除
□ 已剔除：[内容] —— 理由：[法院无法判决/超出主管/缺乏请求权基础等]
□ 无需剔除
```

### 第二步：确定权利请求基础规范

**目标**：定位用户主张的法律关系，找到含构成要件+法律效果的**完全性法条**。

**法条查询规则（强制执行）**：

1. **必须先查 `references/claim-defense-basis-table.md`**。该表覆盖 79 个常见民事案由，按编号-案由索引。
2. 备考表已覆盖的：直接引用 + 标注"已对照备考表"。
3. 备考表未覆盖、案由特殊或涉及 2024 年后修订（如 2023《公司法》、新司法解释）的：**必须 web_search 验证现行有效条文**，不得凭训练数据回忆。
4. 涉及最高院指导案例、纪要的：必须明确引用案号或文号。

**必填输出模板**：

```markdown
## 第二步：确定权利请求基础规范

### 2.1 法律关系定性
[一句话明确：本案系xxx法律关系]

### 2.2 主请求权基础
- 案由（参照《民事案件案由规定》）：
- 备考表编号：第N条 / 备考表未覆盖
- 规范：《xx法》第x条
- 完整条文：[引用条文原文]
- 法律效果：[条文产生何种法律后果]

### 2.3 构成要件分解
| 要件序号 | 构成要件 | 是否需特殊证明 |
|---|---|---|
| ① | ... | 是/否 |
| ② | ... | ... |

### 2.4 备选/竞合请求权
（如不存在竞合，写"本案不存在请求权竞合"）
- 备选规范：《xx法》第x条
- 优劣对比：
  - 主请求权优势：...
  - 备选优势：...
- 推荐选择：[主/备选] —— 理由：...

### 2.5 完全性法条检查
□ 已确认：上述规范为含构成要件+法律效果的完全性法条
□ 警示：本步引用的是倡导性/程序性法条 → 重新定位
```

### 第三步：确定抗辩权基础规范

**目标**：穷尽预判对方可能提出的抗辩，每个抗辩定位实体法依据。

**抗辩类型清单（必须全部排查，不适用的也要写"不适用"）**：

| 类型 | 排查项 |
|---|---|
| 权利消灭抗辩 | 已履行 / 已抵销 / 债权放弃 / 提存 / 混同 |
| 权利阻却抗辩 | 撤销权 / 解除权 / 抵销权 / 同时履行抗辩 / 先履行抗辩 / 不安抗辩 |
| 权利妨碍抗辩 | 合同无效 / 欺诈 / 胁迫 / 显失公平 / 重大误解 / 违反强制性规定 / 违反公序良俗 |
| 时效抗辩 | 诉讼时效届满 / 除斥期间届满 |
| 程序性抗辩 | 管辖异议 / 当事人不适格 / 重复起诉 / 一事不再理 |

**必填输出模板**：

```markdown
## 第三步：确定抗辩权基础规范

### 3.1 抗辩排查矩阵
| 类型 | 排查项 | 适用？ | 抗辩权基础 | 对方提出概率 |
|---|---|---|---|---|
| 权利消灭 | 已履行 | 否 | - | - |
| 权利消灭 | 已抵销 | 是 | 《民法典》第568条 | 中 |
| ... | ... | ... | ... | ... |

（必须包含上方清单的全部排查项，每一项都要表态）

### 3.2 重点抗辩详解
对适用项展开：

#### 抗辩 A：[名称]
- 抗辩权基础：《xx法》第x条
- 完整条文：...
- 构成要件：① ... ② ... ③ ...
- 对方需举证：...
- 我方反制空间：...
```

### 第四步：基础规范构成要件分析

**目标**：将第二步、第三步的规范分解为可逐项验证的要件矩阵。

**必填输出模板**：

```markdown
## 第四步：基础规范构成要件分析

### 4.1 请求权要件矩阵
| 要件编号 | 要件描述 | 举证责任方 | 法律来源 |
|---|---|---|---|
| R1 | ... | 原告/我方 | 《民法典》第x条 |
| R2 | ... | ... | ... |

### 4.2 抗辩权要件矩阵（每个第三步重点抗辩单列一表）
**抗辩 A：[名称]**
| 要件编号 | 要件描述 | 举证责任方 |
|---|---|---|
| A1 | ... | 被告 |
| A2 | ... | 被告 |

### 4.3 举证责任分配特殊规则
□ 本案无举证责任倒置/法律推定 → 适用"谁主张谁举证"
□ 本案存在举证责任倒置 → [说明法律依据，如《民法典》第1230条环境侵权举证责任]
□ 本案存在法律推定 → [说明，如夫妻共同债务、表见代理]
□ 本案存在经验法则推定 → [说明]
```

### 第五步：诉讼主张的检索

**目标**：检查用户事实陈述是否完整覆盖第四步的全部请求权要件。这是定位"要件缺口"的关键步骤。

**必填输出模板**：

```markdown
## 第五步：诉讼主张的检索

### 5.1 要件 → 事实陈述映射
| 要件 | 用户陈述 | 状态 | 缺口/瑕疵 |
|---|---|---|---|
| R1 | "..." | ✅ 已主张且事实清晰 | - |
| R2 | "..." | ⚠️ 已主张但事实模糊 | 缺xx节点 |
| R3 | （无） | ❌ 未主张 | 必须补充 |

状态标注规则：
- ✅ 已主张且事实清晰
- ⚠️ 已主张但事实模糊（需补充细节）
- ❌ 未主张（要件缺口）

### 5.2 完备性结论
□ 完备：全部要件 ✅
□ 有瑕疵：存在 ⚠️ 但无 ❌
□ 严重缺口：存在 ❌

### 5.3 补充事实陈述清单
对 ⚠️ 和 ❌ 项列出需要用户补充的具体事实：
1. [要件编号] 需要补充：...
2. ...
```

### 第六步：争点整理

**目标**：归纳本案事实争点和法律争点。

**必填输出模板**：

```markdown
## 第六步：争点整理

### 6.1 事实争点（按重要性排序）

#### 事实争点 ①
- 内容：...
- 我方主张：...
- 对方可能主张：...
- 关键证据：...

#### 事实争点 ②
...

（如本案无事实争点，明确写"本案事实部分不存在重大争点"）

### 6.2 法律争点

#### 法律争点 ①（实体法适用）
- 内容：[条文选择 / 条文理解 / 法律关系性质]
- 我方观点：...
- 对方观点：...
- 倾向性判断：[我方有利 / 对方有利 / 不确定] —— 理由：...

#### 法律争点 ②（程序法适用）
- 内容：[管辖 / 当事人主体 / 时效 / 举证责任]
- ...

（如本案无某类争点，明确写"无"）
```

### 第七步：要件事实证明（举证规划）

**目标**：以事实争点为核心，规划举证策略，识别证据缺口。

**必填输出模板**：

```markdown
## 第七步：要件事实证明（举证规划）

### 7.1 举证规划矩阵
| 要件事实 | 举证责任 | 现有证据 | 证据强度 | 待补强 |
|---|---|---|---|---|
| ... | 我方 | 借条+转账记录 | 强 | - |
| ... | 对方 | （无） | - | 由对方承担不利后果 |

证据强度标准：
- 强：直接证据 + 形成证据链
- 中：直接证据但孤证 / 间接证据形成链条
- 弱：间接证据无链条 / 仅有当事人陈述

### 7.2 证据缺口清单（按重要性排序）
1. [缺口] — 补强方向：[具体动作，如调取银行流水/申请证人出庭/申请鉴定]
2. ...

### 7.3 法定证据规则触发
□ 本案不触发特殊证据规则
□ 触发：[书证提出命令 / 鉴定 / 现场勘验 / 公证 / 文书强制提交]
  - 触发条件：...
  - 申请时点：...
```

### 第八步：事实认定预判

**目标**：模拟法官在举证质证完成后对每个事实争点的认定结论。**必须输出三态结论之一**，不得用"可能""或许"等模糊表述。

**必填输出模板**：

```markdown
## 第八步：事实认定预判

### 8.1 争点认定预判
| 事实争点 | 预判结论 | 依据 | 不确定度 |
|---|---|---|---|
| ① ... | 支持我方 | 证据链完整 | 低 |
| ② ... | 真伪不明 | 双方均无直接证据 | 高 |

预判结论必为以下三态之一：
- ✅ 支持原告主张事实
- ✅ 支持被告抗辩事实
- ❓ 真伪不明 → 必须在 8.2 显式分配败诉风险

### 8.2 真伪不明状态的败诉风险分配
对每个 ❓ 真伪不明的争点：
- 争点 X → 举证责任在 [我方/对方] → [我方/对方] 承担败诉风险

如无 ❓ 真伪不明争点，写"本案不存在真伪不明状态的争点"。
```

### 第九步：要件归入并作出裁判预测

**目标**：将事实认定结论归入构成要件，输出胜诉概率评估和救济路径建议。**这是唯一可以谈胜诉率的步骤**。

**必填输出模板**：

```markdown
## 第九步：要件归入并作出裁判预测

### 9.1 要件归入结果
**请求权要件归入**：
| 要件 | 事实认定 | 是否成立 |
|---|---|---|
| R1 | ✅ | 成立 |
| R2 | ❓ 真伪不明，原告负举证责任 | 不成立 |

**抗辩权要件归入**（每个重点抗辩单列）：
**抗辩 A：[名称]**
| 要件 | 事实认定 | 是否成立 |
|---|---|---|
| A1 | ✅ | 成立 |
| A2 | ❓ | 不成立 |

抗辩 A 整体：[成立 / 不成立]

### 9.2 裁判预测
□ 全部支持原告：全部请求权要件成立 + 全部抗辩不成立
□ 部分支持：[说明哪些诉请被支持，哪些被驳回]
□ 全部驳回：[请求权要件不成立 / 抗辩权成立]

具体预测裁判主文：
> 一、...
> 二、...
> 三、...

### 9.3 胜诉概率评估
**胜诉概率：[xx%-yy%]**

依据：
- 请求权要件成立度：[全部/大部/部分/少量]
- 抗辩权风险：[低/中/高] —— [说明]
- 真伪不明风险：[低/中/高] —— [说明]
- 政策因素：[无/低/中/高] —— [若有，必须说明]

不确定性边界：
- 关键变量 ①：...（向有利方向变化则概率上限达 yy%；向不利方向变化则概率下限至 xx%）
- 关键变量 ②：...

### 9.4 推荐策略
**优先路径**：[起诉 / 协商 / 和解 / 调解 / 仲裁 / 上诉 / 再审 / 检察监督 / 暂缓行动 / 放弃]

**优先动作清单**（按时间顺序）：
1. [立即可做] ...
2. [一周内] ...
3. [一个月内] ...

**时限提醒**：
```

## 9. 质量红线

- ❌ 不得在第一至八步给出胜诉率结论或暗示性预判
- ❌ 不得跳过、合并、省略任何一步（即使简单案件）
- ❌ 不得用散文叙述替代结构化输出
- ❌ 不得用训练数据中的法条引用替代主动查询（特别是涉及 2024 年后修订的领域）
- ❌ 不得隐藏"真伪不明"状态在"可能""或许"等模糊措辞下
- ❌ 不得在事实严重不清时强行九步走完 → 应停止分析向用户提问

- ✅ 举证责任分配必须明确到具体规则依据
- ✅ 胜诉概率必须给出区间而非点估计，并附不确定性边界
- ✅ 涉政府/群体性/金融稳定案件必须显式标注政策风险
